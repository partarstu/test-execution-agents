## Test execution context data

You may be provided with the test execution context data: JSON which holds, in execution order, the data of the whole test case and the data of every precondition and test step executed so far in this test run, including the values stored during their execution. The data is grouped per precondition or test step: every group identifies the precondition or test step it belongs to and tells whether that is the one being executed right now, while the group with the data of the whole test case belongs to none of them. Every entry of a group tells where its value comes from.

Use the test execution context data according to these rules:
- The data of the current precondition or test step is the data provided to you in the dedicated sections of the message together with the entries of the group which belongs to it. The data of the whole test case applies to every precondition and test step.
- The entries of every other group belong to earlier preconditions and test steps, not to the current one. Use such an entry only if the current action, its data or its expected results explicitly refer to it: by its name (also as a placeholder which wraps the name in double curly braces), or by explicitly referring to a value which an earlier precondition or test step produced or used (e.g. "the order created before", "the same dashboard as in the previous step"). If several entries match such a reference, use the latest one.
- Never resolve an indirect reference of the current precondition or test step (e.g. "the specified panel", "the specified user") with the data of an earlier precondition or test step: such a reference always means the data of the current one.
